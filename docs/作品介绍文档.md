# HHS 智能健康监测平台 — 作品介绍文档

---

## 一、项目详情及使用方式

### 1.1 项目简介

**HHS（Health Hack System）** 是一款面向个人用户的智能健康监测平台，集健康数据追踪、AI 智能分析、实时监控、智能预警、可穿戴设备联动和游戏化激励于一体，帮助用户全面掌握自身健康状况并形成健康生活习惯。

系统采用 **Spring Boot 3 + Vue 3** 前后端分离架构，部署于阿里云 ECS，支持 Docker 容器化一键部署，具备完整的 CI/CD 流水线。

### 1.2 核心功能模块

| 功能模块 | 说明 | 用户价值 |
|---------|------|---------|
| **智能数据录入** | 支持快捷手动录入、AI 语音/文本解析、OCR 图片识别、穿戴设备自动同步四种方式 | 降低数据录入门槛，提升录入效率 |
| **健康指标管理** | 血糖、血压、心率、BMI 等多维度指标的历史记录、趋势分析 | 全面掌握健康数据变化 |
| **实时监控** | 基于 WebSocket 的实时指标采集与动态趋势图 | 佩戴设备时实时查看身体状态 |
| **智能预警系统** | 多级阈值告警、去重合并、趋势预测、AI 辅助分析、恢复通知 | 及时发现健康风险 |
| **AI 健康顾问** | 基于通义千问大模型的智能健康咨询（独立页面 + 全局浮动助手） | 随时获取专业健康建议 |
| **健康评分** | 多维度综合评分（心血管、代谢、体重、生活方式）+ AI 健康报告 | 量化健康状态，指导改善方向 |
| **预防保健** | 健康档案、风险评估、筛查管理与报告对比 | 主动预防，早期发现 |
| **保健追踪** | 睡眠、运动、心情、目标、提醒等日常保健管理 | 培养健康生活习惯 |
| **游戏化激励** | 成就系统、积分体系、连续打卡 | 提升用户粘性和依从性 |
| **多渠道推送** | WebSocket 实时推送、邮件、飞书、企业微信 | 确保重要预警不遗漏 |

### 1.3 使用方式

#### 环境要求

- Java 17+、Node.js 20+、MySQL 8.0+、Redis 7.0+
- 或直接使用 Docker Compose 一键启动

#### 快速启动

```bash
# 方式一：Docker Compose（推荐）
git clone https://github.com/Li3379/health-hack-system.git
cd health-hack-system
cp .env.example .env   # 编辑填写数据库密码、JWT密钥等
docker compose up       # 启动全部服务

# 方式二：本地开发
# 终端1 - 后端
cd hhs-backend && cp .env.example .env && mvn spring-boot:run

# 终端2 - 前端
cd hhs-frontend-v2 && npm ci && npm run dev
```

启动后访问 `http://localhost`（Docker）或 `http://localhost:5173`（本地开发），注册账户即可使用。

#### 生产部署

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

生产环境仅暴露 80 端口，Nginx 反向代理至后端，MySQL/Redis 端口不对外暴露。

## 二、项目亮点

### 亮点一：AI 深度融合的健康管理

系统不是简单地调用大模型 API，而是将 AI 能力深度融入健康管理全流程：

- **AI 智能录入**：用户输入"昨天心率 72，血压 120/80"，系统自动解析为结构化指标数据并入库
- **AI 健康顾问**：基于用户健康档案和历史数据进行个性化咨询，而非通用问答
- **AI 预警分析**：当指标触发预警时，AI 自动分析可能原因并给出建议
- **AI 健康报告**：综合多维度数据生成个性化健康分析报告
- **浮动 AI 助手**：全局悬浮球设计，在任何页面都能快速咨询，附带健康小贴士轮播

### 亮点二：智能预警引擎

区别于简单的阈值判断，系统构建了完整的智能预警子系统：

- **多级阈值**：支持 Warning/Critical 两级高/低阈值
- **去重合并**：相似预警自动合并，避免告警风暴
- **趋势预测**：基于历史数据预测指标趋势，提前预警
- **频率策略**：控制告警频率，避免用户疲劳
- **恢复通知**：指标恢复正常时主动通知用户
- **个性化阈值**：用户可自定义预警阈值，适应个人差异

### 亮点三：四种数据录入方式

为解决健康数据"录入难"的痛点，系统提供四种互补的录入方式：

| 方式 | 场景 | 技术实现 |
|------|------|---------|
| 快捷手动录入 | 日常快速记录 | 表单 + 指标类型智能匹配 |
| AI 文本解析 | 自然语言描述 | 通义千问 NLP 解析 + 结构化输出 |
| OCR 图片识别 | 体检报告、化验单 | 百度 OCR + 模板匹配 + 人工确认 |
| 设备自动同步 | 华为/小米手环 | OAuth2 授权 + 定时同步 + 冲突解决 |

### 亮点四：全链路实时能力

- **WebSocket 实时推送**：指标变更、预警通知实时送达前端
- **实时监控面板**：动态趋势图配合 WebSocket 数据流
- **多渠道推送**：除 WebSocket 外，还支持邮件、飞书、企业微信离线推送
- **前端实时状态**：Pinia store 管理 WebSocket 连接状态，自动重连

### 亮点五：精致的前端设计

- **毛玻璃设计系统**：全局 CSS 自定义属性 + `backdrop-filter: blur()` 毛玻璃效果
- **深色/浅色主题**：完整的设计 Token 体系，一键切换，所有组件自动适配
- **GSAP 入场动画**：页面切换和组件入场使用 GSAP `fromTo` + `clearProps` 动画
- **3D 视觉增强**：Three.js WebGL 球体、3D 倾斜效果等丰富视觉交互
- **ECharts 数据可视化**：健康评分雷达图、仪表盘、迷你趋势线、活动环

### 亮点六：企业级工程实践

- **完整 CI/CD**：5 个 GitHub Actions 工作流覆盖测试、构建、部署、回滚
- **容器化部署**：多阶段 Docker 构建，非 root 用户运行，资源限制
- **安全体系**：JWT 无状态认证、AES-GCM 令牌加密、CORS 分环境配置、路径遍历防护
- **测试覆盖**：46 个后端测试文件（单元/集成/安全/性能），Testcontainers 集成测试
- **代码质量**：Google Checkstyle 强制检查、ESLint + Prettier、JaCoCo 覆盖率门禁

- **主题切换**：顶部栏支持浅色/深色/跟随系统三种主题模式
- **页面过渡动画**：路由切换使用 Vue Transition + GSAP 动画
- **响应式布局**：适配桌面端主流分辨率
- **Markdown 渲染**：AI 对话支持 Markdown 格式，使用 DOMPurify 防 XSS

### 4.3 架构与设计模式

| 模式 | 应用场景 |
|------|---------|
| **分层架构** | Controller → Service → Mapper → Entity 四层分离 |
| **领域事件** | Spring ApplicationEventPublisher 解耦指标录入与告警/评分/积分 |
| **策略模式** | PushChannel 接口 + 4 种推送实现（WebSocket/邮件/飞书/企业微信） |
| **模板方法** | 告警消息模板，支持 `{value}`、`{threshold}` 占位符替换 |
| **观察者模式** | 事件监听器异步处理跨切面关注点 |
| **组合模式** | 健康评分由多个维度评分器组合计算 |

### 4.4 关键技术亮点

1. **Range 分区表**：`realtime_metric` 表按月分区，支持海量实时数据高效查询
2. **AES-GCM 加密**：OAuth 令牌使用 AES-256-GCM 加密存储，保障设备授权安全
3. **多层限流**：AI 接口、认证接口、设备同步接口分别独立限流，防止滥用
4. **冲突解决**：设备同步时使用 `record_time` 时间戳进行数据冲突解决
5. **异步事件处理**：告警生成、评分更新、积分发放均通过异步事件监听器处理，不阻塞主流程
6. **Testcontainers 集成测试**：使用真实 MySQL 容器进行集成测试，确保测试环境与生产一致

### 4.5 部署与运维技术

| 技术 | 用途 |
|------|------|
| Docker 多阶段构建 | 前后端分别构建最小化镜像 |
| Docker Compose | 4 服务编排（前端/Nginx + 后端 + MySQL + Redis） |
| Nginx 反向代理 | SPA 托管 + API 代理 + WebSocket 升级 + 静态资源缓存 |
| GitHub Actions | 5 个 CI/CD 工作流（测试/构建/部署/回滚） |

| 阿里云 ECS | 生产服务器部署 |

## 七、V2.0 优化说明

本项目在原有 V1.0 基础上进行了全面升级优化，从"功能可用的原型"升级为"设计精致、功能完整的健康监测平台"。V2.0 的优化涵盖以下五个方面：

### 7.1 前端设计统一

**优化前**：部分页面（实时监控、保健仪表盘等）使用硬编码的 Element Plus 默认色，与整体暗色设计系统割裂。

**优化内容**：
- 全站替换硬编码颜色为 CSS 自定义属性（Design Tokens）
- 统一毛玻璃（Glassmorphism）卡片效果
- 新增 GSAP 页面入场动画（fromTo + clearProps）
- 新增 3D 视觉增强效果（Three.js WebGL + CSS 3D transforms）
- 统一浮动球 CSS 变量命名

### 7.2 数据可视化升级

**优化前**：ECharts 仅在 3 个页面使用，图表类型单一（基础折线图）。

**优化内容**：
- 创建 `useECharts` 共享 Composable，封装初始化/销毁/主题/自适应
- 新增健康评分雷达图（多维度对比）
- 新增健康评分仪表盘（动态颜色映射）
- 新增 Dashboard 迷你趋势线（Sparklines）
- 新增实时监控仪表盘（ECharts Gauge + WebSocket）
- 新增活动环组件（Activity Rings，SVG 实现）
- 创建 ECharts 统一暗色主题配置

### 7.3 后端核心功能补全

**优化前**：健康分数历史返回假数据、缺少导出功能、缺少提醒系统。

**优化内容**：
- 实现 `health_score_history` 表，分数历史持久化 + 异步记录
- 实现 CSV/Excel/JSON 数据导出（异步生成 + 任务追踪）
- 实现用户自定义提醒系统（Cron 表达式调度）
- 实现体检报告对比功能
- 补全小米健康 API 对接（替换 mock 数据）
- AI 报告降级提示优化

### 7.4 用户粘性功能

**优化前**：用户缺乏持续使用的动力。

**优化内容**：
- 游戏化系统：成就定义 + 积分体系 + 连续打卡追踪
- 健康目标管理：目标设定 + 进度记录 + 完成统计
- 心情追踪：每日心情/精力/压力/睡眠质量记录
- 健康提醒：自定义提醒，支持 Cron 调度

### 7.5 高级分析功能

**优化内容**：
- 多维度统计接口（日/周/月统计）
- 健康趋势分析（指标趋势 + 健康等级趋势）
- 保健指标综合评分（Wellness Scorer）
- 筛查评分器（Screening Scorer）
- 风险评估分析器（Risk Analyzer）

### 7.6 CI/CD 与工程化

**优化前**：缺少自动化部署和版本管理。

**优化内容**：
- 新增 5 个 GitHub Actions 工作流（后端CI、前端CI、Docker构建发布、手动部署、版本回滚）
- 新增 GHCR 镜像托管 + SHA/版本标签
