# HHS 智能健康监测平台 — 项目演示脚本

> **适用场景**：项目答辩 / 竞赛展示 / 产品介绍  
> **建议时长**：10-12 分钟  
> **录制工具**：OBS Studio / Screen Studio / 系统自带录屏  
> **分辨率建议**：1920×1080，60fps  
> **主题建议**：使用深色主题录制（视觉效果更佳，毛玻璃效果突出）

---

## 📋 演示前准备清单

| 准备项 | 说明 | 是否完成 |
|--------|------|---------|
| 启动后端服务 | `docker compose up` 或 `mvn spring-boot:run` | ☐ |
| 启动前端服务 | `npm run dev` 或 `docker compose up` | ☐ |
| 配置 DashScope API Key | 确保 AI 功能可用（`application-dev.yml` 中的 `langchain4j.dashscope.api-key`） | ☐ |
| 配置百度 OCR API Key | 确保 OCR 识别功能可用 | ☐ |
| 准备示例数据 | 提前录入若干天健康数据（血糖、血压、心率、体重、睡眠等），让仪表盘有数据显示 | ☐ |

### 场景 4：智能数据录入（约 3 分钟）

> **这是系统的核心亮点场景，建议详细演示**

#### 4.1 四种录入方式总览（15 秒）

| 项目 | 内容 |
|------|------|
| **画面** | 导航到"数据录入"页面 |
| **操作** | ① 点击左侧导航栏「数据录入」菜单项<br>② 页面展示：顶部 4 个统计卡片 + 下方 4 个功能卡片区域 |
| **旁白** | 接下来我们进入系统的**核心功能——数据录入**。为解决健康数据"录入难"的痛点，系统提供了**四种互补的录入方式**。页面上方展示了今日录入概览，下方依次是：快捷录入、AI 智能录入、穿戴设备同步和 OCR 图片识别。我们先来看第一种。 |

#### 4.2 快捷手动录入（40 秒）

| 项目 | 内容 |
|------|------|
| **画面** | 点击「快捷录入」卡片 → 点击"血糖"按钮 → 弹出录入对话框 → 输入 5.6 → 选择日期 → 保存 → 提示成功 |
| **操作** | ① 点击「快捷录入」卡片（左上角第一张）<br>② 在弹出的一排快捷按钮中点击「血糖」<br>③ 弹出录入对话框，输入数值 `5.6`<br>④ 确认日期为当天<br>⑤ 点击「保存」<br>⑥ 观察保存成功的提示 |
| **旁白** | 首先是**快捷手动录入**——最直接的方式。点击需要记录的指标按钮，比如血糖，在弹出的对话框中输入数值，系统会自动校验数值是否在有效范围内，点击保存即可完成录入。这种方式适合日常快速记录单一指标，一秒钟完成。 |

#### 4.3 AI 智能录入（1 分钟）

| 项目 | 内容 |
|------|------|
| **画面** | 切换到「AI 智能录入」卡片 → 输入自然语言 → 点击智能解析 → 展示解析结果 → 确认录入 |
| **操作** | ① 点击「AI 智能录入」卡片（右上角）<br>② 在文本框中输入：`今天血糖5.6，心率72，走了8000步，睡眠7.5小时`<br>③ 点击「智能解析」按钮<br>④ 等待 AI 返回解析结果（展示识别的指标、数值、置信度）<br>⑤ 勾选需要保存的指标<br>⑥ 点击「确认录入」 |
| **旁白** | 第二种是**AI 智能录入**——这是系统的一大亮点。用户只需用自然语言描述，比如"今天血糖 5.6，心率 72，走了 8000 步"，系统通过**通义千问大模型**自动解析，从文本中提取结构化的健康指标。可以看到，系统成功识别出了血糖、心率、步数和睡眠时长四个指标，并给出了置信度评估。绿色高置信度表示可以放心保存，用户确认后一键入库。页面上方还显示了今日剩余的使用次数。 |

#### 4.4 OCR 图片识别（1 分钟）

| 项目 | 内容 |
|------|------|
| **画面** | 切换到「OCR 图片识别」卡片 → 选择识别类型 → 上传图片 → 开始识别 → 显示识别结果 → 确认录入 |
| **操作** | ① 点击「OCR 图片识别」卡片（右下角）<br>② 选择识别类型「体检报告」<br>③ 拖拽或点击上传一张准备好的体检报告图片<br>④ 点击「开始识别」按钮<br>⑤ 等待百度 OCR 返回识别结果<br>⑥ 展示识别的化验指标列表<br>⑦ 点击「确认录入」 |
| **旁白** | 第三种是**OCR 图片识别**。用户可以将体检报告单、药品标签或营养标签拍照上传，系统通过**百度 OCR 接口**识别图片中的文字，提取出化验指标数值。这里我们上传一张体检报告，系统自动识别出了其中的检验指标。对于已有大量纸质报告的用户来说，这种录入方式极大降低了数据迁移成本。 |

#### 4.5 穿戴设备同步（30 秒）

| 项目 | 内容 |
|------|------|
| **画面** | 切换到「穿戴设备同步」卡片 → 展示支持的平台列表 → 点击连接 → OAuth 授权流程 → 同步成功 |
| **操作** | ① 点击「穿戴设备同步」卡片（左下角）<br>② 鼠标划过四个平台图标（华为健康、小米运动、微信运动、Apple Health）<br>③ 点击一个平台（如华为健康）的「连接」按钮<br>④ 展示 OAuth 授权页面（或跳转提示）<br>⑤ 授权成功后展示「已连接」状态<br>⑥ 点击「同步」按钮<br>⑦ 展示同步成功提示和同步的数据条数 |
| **旁白** | 第四种是**穿戴设备自动同步**。系统支持华为健康、小米运动、微信运动和 Apple Health 四大主流平台，通过 **OAuth 2.0 授权协议**安全连接。用户只需首次授权，后续系统可以定时自动同步设备数据。同步过程中采用**时间戳冲突解决算法**确保数据一致性，OAuth 令牌使用 **AES-256-GCM 加密存储**，保障用户授权安全。 |

#### 4.6 最近录入记录（15 秒）

|------|------|
| **画面** | 滚动到页面底部 → 展示最近录入记录表格 |
| **操作** | ① 向下滚动页面<br>② 指向「最近录入记录」表格，展示刚才通过不同方式录入的数据 |
| **旁白** | 页面底部展示了最近录入的健康记录，无论通过哪种方式录入的数据，都会统一汇总到这里，方便用户追溯和管理。 |

## 📝 附录：备用 Q&A 参考

以下是为演示后答辩环节准备的可能问题及回答要点：

### Q1：系统的核心技术难点是什么？

- **AI 深度融合**：不是简单调用 API，而是将 AI 嵌入数据录入（NLP 解析）、健康分析（评分报告）、预警分析（趋势预测）全流程
- **多源数据一致性**：四种录入方式 + 设备同步的数据冲突解决（时间戳优先算法 + 5 分钟去重窗口）
- **实时性保障**：WebSocket 长连接 + MySQL Range 分区表 + Redis 缓存三级架构
- **安全性设计**：JWT 无状态认证 + AES-256-GCM 令牌加密 + 三层限流 + BCrypt 密码哈希

### Q2：与其他健康管理应用相比，差异化优势是什么？

- **AI 深度融合**：不只是一个聊天机器人，而是嵌入数据录入、分析、预警全流程
- **四种数据录入方式**：覆盖全场景，真正解决"录入难"痛点
- **企业级工程实践**：完整的 CI/CD（5 个 GitHub Actions 工作流）、Docker 容器化部署、安全审计、46 个测试文件
- **双主题设计 + 精致视觉**：毛玻璃设计、GSAP 动画、Three.js 3D 增强

### Q3：数据安全性如何保障？

- 密码：BCrypt（strength 10）加密存储
- 认证：JWT 无状态（HS256，256-bit secret，7 天有效期）
- 传输：HTTPS 加密通信
- 设备令牌：AES-256-GCM 加密存储
- 接口：CORS 分环境配置 + 路径遍历防护
- 限流：登录 10 次/5 分钟、AI 20 次/天（访客 3 次/天）、设备同步 10 次/分钟

### Q4：如何保证预警不遗漏？

- **四层推送保障**：WebSocket 实时推送 + 邮件 + 飞书 + 企业微信
- **预警去重合并**：同指标同级别 1 小时内、数值偏差不超过 10% 时合并为一条并累加次数
- **恢复通知**：指标恢复正常时主动推送
- **侧边栏 Badge**：持久显示未读预警数量

### Q5：系统的可扩展性如何？

- **策略模式**：PushChannel 接口（4 种推送实现）、DeviceDataSyncStrategy 接口（4 种设备平台），新增实现无需修改核心逻辑
- **事件驱动**：Spring ApplicationEventPublisher 解耦模块（ScoreUpdatedEvent、MetricRecordedEvent、AlertGeneratedEvent）
- **数据库 Range 分区**：`realtime_metric` 按月分区，支持海量实时数据
- **CI/CD 完整流水线**：自动构建 → 测试 → Docker 镜像发布 → ECS 部署 → 版本回滚
