    1. 类型与接口定义：
       - 定义 `MetricTier` 联合类型：'NORMAL' | 'WARNING' | 'CRITICAL' | 'HARD_BOUND'。
       - 定义 `MetricEvaluation` 接口：包含 `tier: MetricTier`, `status: 'success' | 'warning' | 'danger' | 'hard_danger'`, `badgeText: string`, `message: string`, `canSave: boolean`, `isCritical: boolean`, `isHardLimit: boolean`。
    
    2. 核心临床危急值字典 `PANIC_LIMITS`（严格遵循 D-05 锁定决策）：
       - `systolicBP`: `{ min: 70, max: 180 }`
       - `diastolicBP`: `{ min: 40, max: 110 }`
       - `bloodGlucose`, `fastingGlucose`, `postprandialGlucose`: `{ min: 2.8, max: 16.7 }`
       - `heartRate`: `{ min: 45, max: 140 }`
       - `bodyTemperature`: `{ min: 35.0, max: 39.5 }`
       - `bloodOxygen`: `{ min: 90 }` (血氧 <= 90% 为危急重症)
    
    3. 纯函数 `evaluateMetricValue(value, def)` 实现（遵循 D-02 锁定决策与 Pitfall 4 规范）：
       - 空值防呆：若 `value === undefined || value === null || isNaN(value)` 返回 null。
       - 无元数据保护：若未提供 `def`，返回安全兜底状态（tier: 'NORMAL', status: 'success', canSave: true）。
       - Tier 4 生理不可能极限判定（最高优先级）：`value < def.hardMin || value > def.hardMax`，返回 tier: 'HARD_BOUND', status: 'hard_danger', badgeText: '超出存活极限', canSave: false, isHardLimit: true，说明文案严格对齐后端规范 `${def.displayName}有效生理区间为 ${def.hardMin} ~ ${def.hardMax} ${def.unit}，请核对是否多输了数字`。
       - Tier 3 急危重症判定：查询 `PANIC_LIMITS[def.canonicalKey]`，若触发危急线，返回 tier: 'CRITICAL', status: 'danger', badgeText: '严重危急值', canSave: true, isCritical: true, isHardLimit: false，文案提示达到临床危急重症预警线，保存前请二次确认。
       - Tier 2 预警偏差判定（遵循 D-02 与 VAL-03）：若 `value < def.normalMin || value > def.normalMax`，返回 tier: 'WARNING', status: 'warning', badgeText: isHigh ? '指标偏高' : '指标偏低', canSave: true, isCritical: false，文案明确指出处于偏高/偏低状态，但完全允许正常保存。
       - Tier 1 正常参考区间：返回 tier: 'NORMAL', status: 'success', badgeText: '正常参考区间', canSave: true, isCritical: false。
    
    4. 血压生理倒置检测纯函数 `checkBloodPressureInversion(systolic, diastolic)`（遵循 D-04 决策）：
       - 若收缩压或舒张压任一为空/NaN，返回 false。
       - 若 `systolic <= diastolic`，返回 true；否则返回 false。
    
    5. 编写完整单元测试 `metricValidation.spec.ts`：
       - 覆盖 23 项核心指标的四梯度边界，包括正常收缩压 120 (T1)、高血压 150 (T2 非阻塞)、高血压危象 190 (T3 危急二次确认)、不可能数值 350 (T4 拦截)；
       - 覆盖空腹血糖 5.0 (T1)、8.0 (T2)、18.0 (T3)、30.0 (T4)；
       - 覆盖 0 值的合规处理（如步数 0 步或运动 0 分钟不判定为空）；
       - 覆盖收缩压 <= 舒张压（如 80/120）倒置返回 true 与正常（120/80）返回 false。

    1. 组合式函数入参契约：
       - `metricKeyRef: Ref<string | undefined>`
       - `valueRef: Ref<number | undefined>`
       - `diastolicRef?: Ref<number | undefined>`
    
    2. 响应式元数据检索：
       - 调用 `useMetricMetaStore()` 获取全局指标字典。
       - 计算 `canonicalKey`: 通过 `toCanonicalKey(metricKeyRef.value)` 规范化当前 key。
       - 计算 `isBloodPressure`: 判定 `canonicalKey.value === 'systolicBP' || metricKeyRef.value === 'bloodPressure'`。
       - 计算 `definition`: 响应式读取 `metaStore.getDefinition(metricKeyRef.value)`。
       - 计算 `diastolicDef`: 若为血压指标，读取 `metaStore.getDefinition('diastolicBP')`。
    
    3. 响应式生理评估与状态派生（遵循 D-02 与 D-04 决策）：
       - `primaryEval`: 计算属性，调用 `evaluateMetricValue(valueRef.value, definition.value)`。
       - `diastolicEval`: 计算属性，针对血压舒张压调用 `evaluateMetricValue(diastolicRef.value, diastolicDef.value)`。
       - `isInverted`: 计算属性，当为血压指标且双字段均有值时调用 `checkBloodPressureInversion(valueRef.value, diastolicRef.value)`。
       - `hasCritical`: 计算属性，若主字段或舒张压任一 `isCritical === true` 则返回 true。
       - `isSaveBlocked`: 计算属性，当主字段或舒张压达到 Tier 4 物理极限 (`isHardLimit`)，或存在血压倒置 (`isInverted`) 时返回 true，其余情况（正常、预警偏差、危急重症）均返回 false。
    
    4. 血压原子一键对调方法 `swapBloodPressure`（严格遵循 D-04 锁定决策）：
       - 检查若为血压指标且 `diastolicRef` 存在，原子交换 `valueRef.value` 与 `diastolicRef.value` 的数值：
         `const temp = valueRef.value; valueRef.value = diastolicRef.value; diastolicRef.value = temp;`
       - 交换后由于响应式计算，`isInverted` 自动刷新为 false，解除倒置警示。
    
    5. 编写单元测试 `useMetricValidation.spec.ts`：
       - 使用 Pinia `setActivePinia(createPinia())` 初始化测试环境；
       - 测试常规指标（如心率、血糖）响应式改变数值时 `primaryEval` 的梯度切换；
       - 测试血压指标录入时收缩压与舒张压的各自独立评估；
       - 测试血压倒置场景（例如收缩压 80、舒张压 120），验证 `isInverted.value === true` 且 `isSaveBlocked.value === true`；
       - 执行 `swapBloodPressure()`，验证收缩压变为 120、舒张压变为 80，`isInverted.value === false` 且解除阻塞。
