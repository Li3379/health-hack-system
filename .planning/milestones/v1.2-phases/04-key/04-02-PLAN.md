<objective>
实现请求级物理生理极限硬拦截与服务层多格式 Key 兼容治理。
基于 Jakarta Validation 框架构建类级别注解 `@ValidMetricRecord` 与 `MetricRecordValidator`，在 Controller 接收 `HealthMetricRequest` 时硬性拦截物理不可能数据，生成统一格式的友好错误反馈；移除 DTO 中粗暴的 1000 上限约束，并在反序列化阶段自动执行 Key 规范化；重构 `HealthMetricServiceImpl` 使其在按 `metricKey` 检索时通过别名集合透明展开 SQL `IN (...)`，确保历史存量数据与增量数据无缝兼容；提供生产环境可选执行的幂等 SQL 清洗补丁。

Purpose: 保护系统免受物理荒谬脏数据污染，同时杜绝将病理体征误拦截为非法的缺陷，并彻底解决多命名风格下的数据查询断层。
Output: `ValidMetricRecord.java`, `MetricRecordValidator.java`, `HealthMetricRequest.java` 改造, `HealthMetricServiceImpl.java` 改造, `v1.1_normalize_metric_keys.sql`, 以及对应的高覆盖度自动化验证测试。
</objective>
