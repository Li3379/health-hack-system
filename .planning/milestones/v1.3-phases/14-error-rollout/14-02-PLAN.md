<objective>
Deliver A-1 pre-change 2: the single global declaration of what an errored field looks like, which ERR-03's inline rollout depends on.

This exists because of a concrete suppression, not a preference. The project stylesheet gives `.el-input__wrapper` and `.el-select__wrapper` a real 1px border and explicitly kills their box-shadow with `!important` (theme.css:504-506 and :672-677). Element Plus's own errored-field visual is an inset box-shadow with **no** `!important`. The result today is that an errored text input or select looks exactly like a healthy one — the only signal is the red text underneath, which a user scanning a 15-field form will not associate with the field. Textarea is the opposite case: the project stylesheet never touches it, so EP's inset shadow still works there. Two control families therefore need two different declarations, and neither can be written per page.

Purpose: without this block, the 87-site rollout would produce forms whose inline red text floats above an unmarked input, and every migrator would be tempted to write a local `:deep()` override — which is exactly the drift Contract 4.2 forbids.

Output: one appended block in `theme.css` and one spec that pins both the CSS shape and the `.is-error` anchor against the real component library.
</objective>
