<objective>
Wire the two list-plus-dialog pages that carry the rollout's clearest ambiguous field names, and prove the ERR-03/ERR-05 pair end-to-end before the remaining batches copy the shape. This plan implements D-01's user-visible-path rule and D-04's zero-prompt-on-cancel rule for its delete handlers.

These two pages are first for a reason. Both have a `title` field whose correct label differs from the global `标题`, and the goal page has three different meanings for `value` (当前值, 进度值, and the global 指标数值). Contract 4.5 rule 4 is explicit: these must be resolved with a per-call `labels` override, never by mutating the global table — because mutating it would then mislabel `title` on the profile and threshold pages. Doing this batch first establishes the override pattern the other form plans reuse.

They are also the batch where the canonical submit shape has to be settled, because wiring inline errors *requires* `showError`'s return value: `apply(err)` needs the normalised `ApiError`, and the only supported way to obtain it while also presenting the failure is `showError`'s return. So this plan necessarily converts the submit-path toasts as part of the wiring rather than leaving them for a later wave — a submit handler cannot be "inline-wired but still toasting through `ElMessage.error`" without violating the zero-toast-on-validation rule.

Purpose: leave both dialogs in a state where a 400 shows a summary and inline errors with the form untouched and the dialog open, which is ERR-03 and ERR-05 together.

Output: two fully wired pages, the ledger created with its header and first rows, and two specs that pin the behaviour — including the form-preservation snapshot that makes ERR-05 testable rather than aspirational.
