<objective>
Establish the frontend contract for phase 12: metadata types carrying `alertable` + `recommended`, the offline fallback mirroring the backend, store computeds for the picker, and the pure validation function that mirrors the backend constraint.

Purpose: Every later frontend task consumes one of these four surfaces. Building the contract first means the wizard and zone bar are assembled from typed, already-tested primitives instead of inventing shapes inline — and it keeps the frontend from ever hardcoding a metric whitelist (D-03).
Output: A compiling, fully-typed metadata contract plus a pure validation module with its own test suite.
</objective>
