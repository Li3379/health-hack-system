<objective>
Add the estimate badge to the health-score page so the second result surface discloses estimation and links to the profile page.

Purpose: PRF-06 names both result pages. The score page is the one place a user sees a number derived partly from profile defaults, and its `HealthScoreVO` now carries `profileCompleteness` and `assumptions`. Because `HealthScoreServiceImpl` returns `createDefaultScore()` with `profileCompleteness` deliberately null for users without metrics, this page is also where a null-vs-zero distinction has real consequences: showing a badge there would tell a brand-new user their profile was used when no score was even computed.

This plan also closes the one pre-existing copy violation in the file it touches (plan-check W6): the report-generation dialog's secondary button renders the bare word 取消, which the approved Copywriting Contract forbids. Since the plan already rewrites this file's template and re-typesets its buttons, it renames that label to 放弃生成 (UI-SPEC §Appendix R-1) and adds a grep guard.

Output: the badge wired into `health/Score.vue`, the renamed dialog button, and a focused spec for both.
</objective>
