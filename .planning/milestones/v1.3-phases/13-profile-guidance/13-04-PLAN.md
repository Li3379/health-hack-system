<objective>
Extend the risk-assessment response with the two disclosure fields, capturing assumptions at the real substitution sites and recomputing them on read from the current profile — both through the one sentence source created in 13-01.

Purpose: PRF-05 applies to the risk response as well as the score response. RESEARCH Pitfall 7 established that `risk_assessment` has no assumption columns and `schema.sql` only runs on an empty volume, so persisting the assumptions would need a migration this phase deliberately avoids. The RESOLVED decision is read-time recomputation: the badge means 「当前档案下，该评估所依赖的默认假设」.

The critical design constraint (plan-check B2) is that the pre-create backfill panel and this post-create disclosure must show the SAME sentences for the same profile. Two independent derivations cannot guarantee that: a per-field join over `completeness.fields[].assumption` emits three sentences for a null profile while this engine returns one generic sentence, and a bare keyword test labels a supplied `父亲有高血压` as 「缺少家族病史」. So this plan does not invent its own sentence logic — it consumes `ProfileFieldCatalog.assumptionsFor` (13-01), which branches on profile presence and on the supplied-vs-empty family history exactly as the engine does, and it delegates `hasFamilyHistory` to `ProfileFieldCatalog.mentionsDiabetes` so even the engine's own boolean uses the shared predicate.

Output: The extended `RiskAssessmentVO` record, collector-aware `RiskRuleEngine`, `toVO` recomputation from the shared source, and `RiskAssessmentAssumptionsTest` covering all four reachable substitution paths plus a parity assertion.
</objective>
