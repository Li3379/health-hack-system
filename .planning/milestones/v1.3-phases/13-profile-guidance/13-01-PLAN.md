<objective>
Create the authoritative backend completeness source: a pure 9-field catalog plus a weighted calculator that returns score / level / filledCount / totalCount / hasProfile / assumptions / fields[], and a single shared `assumptionsFor` function that produces the substitution sentences both the risk engine and the pre-create backfill panel will use.

Purpose: D-01 locks completeness to the backend and forbids the frontend from computing it. Every later surface (profile page header, dashboard compact row, banner trigger, risk badge, backfill panel) reads the same object, so the weighting, the three level thresholds and the per-field `reason` copy are decided exactly once, here. The existing `ProfileScorer` hard-coded deduction scheme (`-10/-15/-10/-15`, empty profile → 70) cannot serve this: it produces no field list, no level, and its 70-for-empty value would make an empty profile look half-complete.

The `assumptions` list is the second thing decided here, and it is decided deliberately as a list, not as a per-field join. Two reachable states cannot be expressed by joining `fields[].assumption`: a brand-new user with no profile row gets ONE generic sentence (`未填写健康档案，风险得分按通用参考值估算`) rather than the three per-field sentences for birthDate/bmi/familyHistory, and a user who supplied `父亲有高血压` gets NO family-history sentence even though their `familyHistory` field is filled but keywordless. `ProfileFieldCatalog.assumptionsFor(HealthProfile)` therefore branches on profile presence and on the exact predicate the risk engine uses, and both 13-04 (post-create disclosure) and 13-09 (pre-create panel) consume it — so the panel cannot promise substitutions the engine will not make. D-03's requirement that assumptions be captured where the substitution actually happens is satisfied because 13-04's substitution branches call this same predicate rather than re-deriving it.

Output: `ProfileFieldCatalog` (catalog + `assumptionsFor`), `ProfileCompletenessCalculator`, `ProfileCompletenessVO`, `ProfileFieldStatusVO`, and the two Wave-0 test classes that pin them. No HTTP surface yet (13-02), no score/risk VO changes (13-03/13-04).
</objective>
