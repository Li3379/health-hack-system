       - 文件内注释引用 D-09：静默由调用点显式标记，无 URL 模式自动判定。

    3) 新建 `src/utils/appError.ts`（纯函数模块，**禁止** import pinia / 任何 store / vue-router / element-plus）：
       - `export type ErrorKind = 'validation' | 'business' | 'auth' | 'network' | 'server' | 'cancel' | 'unknown'`
       - `export class ApiError extends Error`，构造签名 `(message: string, readonly kind: ErrorKind, readonly status?: number, readonly code?: string, readonly fieldErrors: Record<string, string> = {}, readonly formField?: string, readonly retryable = false)`；`super(message)` 后 `this.name = 'ApiError'`。
       - `export const CANCEL_SENTINELS = ['cancel', 'close'] as const`
       - `export function isCancel(raw: unknown): boolean` —— 字符串命中 `CANCEL_SENTINELS` 返回 true；否则检查 `raw?.name === 'CanceledError' || raw?.name === 'AbortError' || raw?.code === 'ERR_CANCELED'`（per D-12：这五种形态统一识别并完全忽略，不产生任何提示）。
       - `export function normalizeApiError(raw: unknown): ApiError`，**按此顺序**分类（顺序即契约，取消必须最先）：
         1. `isCancel(raw)` → `new ApiError('', 'cancel')`
         2. 取 `const err = raw as any; const data = err?.response?.data; const status = err?.response?.status`
         3. `data?.fieldErrors?.length` 非空 → 逐项把 `fe.field → fe.message` 收进 `Record<string,string>`（同字段重复用 `；` 连接），返回 `new ApiError(data.message || '请检查以下填写内容', 'validation', status, data.errorCode, map)`
         4. `status === 401` → `new ApiError('登录已过期，请重新登录', 'auth', 401)`
         5. `!err?.response` → `new ApiError('网络连接异常，请检查网络后重试', 'network', undefined, undefined, {}, undefined, true)`
         6. `status >= 500` → `new ApiError('服务暂时不可用，请稍后重试', 'server', status, data?.errorCode, {}, undefined, true)`
         7. `data?.code && data.code !== 200` → `new ApiError(data.message || '', 'business', status, data.errorCode)`
         8. 兜底 → `new ApiError(data?.message || '服务暂时不可用，请稍后重试', 'server', status)`
       - 不导出 `showError`（下一个计划），不 import `ERROR_MESSAGES`，不在本文件做 fallback key 解析。

       - rejected 分支：`const apiError = normalizeApiError(error)`；`if (apiError.kind === 'cancel') return Promise.reject(apiError)`；`if (apiError.kind === 'auth')` 进入模块级 `handling401` 闩锁（见下）；`const silent = (error.config as any)?.silent === true`；**无论 silent 与否都 `return Promise.reject(apiError)`**（D-10：silent 只影响展示，不改变拒绝）。

       - **401 提示归属（必须写进代码注释，且注释里不得出现 ElMessage 字面量，以免破坏下方的零引用门禁）**：`stores/auth.ts` 的 `logout()` 自身会发一条「已退出登录」提示。因此 401 链路唯一的用户可见提示来自 logout，拦截器不得再加第二条（否则一次令牌过期出现两条消息）。测试用 spy 断言 `logout` 恰好一次，即等价于"恰好一条提示"。
       - 保留 `useAuthStore` 的 import（store 已在现有代码中导入，不构成新的循环风险）。
