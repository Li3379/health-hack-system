    打通一条真实链路：后端两种失败形状 → 拦截器 → 调用方拿到同一个 `ApiError`。

    1) `src/types/api.ts` 顶部追加（在现有 `ApiResponse` 之前或之后均可，不得改动既有三字段）：
       - `export interface FieldError { field: string; message: string; code?: string }`
       - 给 `ApiResponse<T>` 追加两个可选字段：`errorCode?: string`、`fieldErrors?: FieldError[]`。**必须可选** —— 既有调用点与测试都按三字段构造对象。

    2) 新建 `src/types/axios.d.ts`：
       - 首行 `import 'axios'`，随后 `declare module 'axios' { export interface AxiosRequestConfig { silent?: boolean } }`。
       - 文件内注释引用 D-09：静默由调用点显式标记，无 URL 模式自动判定。
       - `tsconfig.json` 的 `include` 已含 `src/**/*.d.ts`，不需改 tsconfig。

    3) 新建 `src/utils/appError.ts`（纯函数模块，**禁止** import pinia / 任何 store / vue-router / element-plus）：
       - `export type ErrorKind = 'validation' | 'business' | 'auth' | 'network' | 'server' | 'cancel' | 'unknown'`
       - `export class ApiError extends Error`，构造签名 `(message: string, readonly kind: ErrorKind, readonly status?: number, readonly code?: string, readonly fieldErrors: Record<string, string> = {}, readonly formField?: string, readonly retryable = false)`；`super(message)` 后 `this.name = 'ApiError'`。
       - `export const CANCEL_SENTINELS = ['cancel', 'close'] as const`
       - `export function isCancel(raw: unknown): boolean` —— 字符串命中 `CANCEL_SENTINELS` 返回 true；否则检查 `raw?.name === 'CanceledError' || raw?.name === 'AbortError' || raw?.code === 'ERR_CANCELED'`（per D-12：这五种形态统一识别并完全忽略，不产生任何提示）。
       - `export function normalizeApiError(raw: unknown): ApiError`，**对已是 `ApiError` 的输入幂等直通**（返回同一引用，绝不重新分类）。**按此顺序**分类（顺序即契约；四条不可调换的约束：ApiError 直通必须最先，取消其次，401 必须早于信封业务码，信封业务码必须早于 5xx）：
         0. `if (raw instanceof ApiError) return raw` —— **必须是第一个分支，早于 `isCancel`**。理由：`request.ts` 的 `Promise.reject(normalizeApiError(...))` 抛出的就是 `ApiError`；11-04 的 `showError` 首行、11-05 的 `apply(err)`、11-07 的三处 `showError(error, ...)` 都会把它再喂回来。`ApiError` 没有 `response` 属性，若缺这道直通，第 5 步 `!err?.response` 会把每一条拦截器错误改判成 `network`，产生三处生产故障：(a) 校验失败 toast「网络连接异常」且内联/汇总永不出现；(b) `code` 丢失导致 `resource.exists` 的『打开编辑』消失（D-08）；(c) cancel 的 `kind='cancel'` 被覆盖成 `network`，弹出一条本应完全忽略的提示（D-12）。**不要**把它写成"只对某些 kind 直通"，也不要按 message 内容猜测 —— 幂等性必须只依赖类型。
         1. `isCancel(raw)` → `new ApiError('', 'cancel')`
         2. 取 `const err = raw as any; const data = err?.response?.data; const status = err?.response?.status`
         3. `data?.fieldErrors?.length` 非空 → 逐项把 `fe.field → fe.message` 收进 `Record<string,string>`（同字段重复用 `；` 连接），返回 `new ApiError(data.message || '请检查以下填写内容', 'validation', status, data.errorCode, map)`
         4. `status === 401` → `new ApiError('登录已过期，请重新登录', 'auth', 401)`。**必须排在信封业务码之前**：11-01 的认证分支返回的是真实 HTTP 401，其响应体里 `code` 也是 401（`!= 200`）；若先判业务码，令牌过期会被误判成 business，闩锁不触发、不 logout，一次会话过期就变成静默失败。
         5. `!err?.response` → `new ApiError('网络连接异常，请检查网络后重试', 'network', undefined, undefined, {}, undefined, true)`。**仅对原生 Axios 错误形态生效** —— `ApiError` 已在第 0 步直通返回，永远不会到达这里，所以这条分支不会把类型化错误误判成断网。
         6. `status >= 500` → `new ApiError('服务暂时不可用，请稍后重试', 'server', status, data?.errorCode, {}, undefined, true)`。这里只覆盖**真实 HTTP 5xx**（网关/容器层返回）。
         7. **信封业务失败（HTTP 200 + 信封 code != 200）**：`typeof data?.code === 'number' && data.code !== 200` → `new ApiError(data.message || '', 'business', status, data.errorCode)`。判定只读**信封里的 `data.code`**，不读 `status`、也不看 code 的数值大小。**这一步必须早于任何 status 相关的 5xx 判断才能安全存在**，而它的真实性由两点保证：(a) `request.ts` 的 fulfilled 分支把假 response 的 `status` 固定写成 200（见下），所以第 6 步不会截胡；(b) 真实 HTTP 5xx 的响应体不带信封 `code`（Axios 的 error 分支拿到的是网关/容器错误页），所以第 7 步也不会误吞。**若把判定改成读 `status` 或让 `request.ts` 拿 `res.code` 当 status，每一条 `BusinessException`（经 `parseCodeToInt` 回退后信封 code 恒为 500）都会被改判成 `server` 并丢掉后端中文 message，违反 D-05 与 ROADMAP 准则 2。** 同时用 `typeof === 'number'` 守住 `code` 为字符串的旧信封形态（如旧 `AUTHENTICATION_REQUIRED`），字符串码不进入本分支、落到兜底。
         8. 兜底 → `new ApiError(data?.message || '服务暂时不可用，请稍后重试', 'server', status)`
       - **已知语义边界（写进代码注释，避免后续"修正"成错误方向）**：本后端把通用 500/系统异常也包成 HTTP 200 信封（`GlobalExceptionHandler.handleException` / `handleSystemException` 返回 `Result<Void>` 而非 `ResponseEntity`），因此这类失败会走第 7 步归为 `business`，文案仍是后端下发的固定中文 `服务暂时不可用，请稍后重试`，只是不带重试按钮。`server` 分支保留给真实的传输层 5xx。这是刻意的：ROADMAP 准则 2 只要求"一条中文提示"，不要求所有服务端故障都可重试。
       - 不导出 `showError`（下一个计划），不 import `ERROR_MESSAGES`，不在本文件做 fallback key 解析。
