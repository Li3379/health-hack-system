    逐层打通一条真实的校验失败路径：DTO 字段违规 + 类级违规 → GlobalExceptionHandler → Result → HTTP 400 JSON。全部产出必须能被一个直接调用 handler 的单元测试验证，不启动 Spring 上下文、不依赖 Docker。

    1) 新建 `com.hhs.vo.FieldErrorVO`，声明为 `public record FieldErrorVO(String field, String message, String code)`，字段顺序固定为 field、message、code（与前端 `FieldError` 接口一致），附类级 Javadoc 说明它替代旧的 `"field: msg"` 字符串拼接。不改动 `vo` 包内其它类。

    2) 改造 `com.hhs.common.Result<T>`：
       - 保留 `private int code; private String message; private T data;` 三字段不动，`parseCodeToInt` 一字不改。
       - 新增三字段，各自单独标注 `@com.fasterxml.jackson.annotation.JsonInclude(JsonInclude.Include.NON_EMPTY)`：`private String errorCode;`、`private java.util.List<FieldErrorVO> fieldErrors;`、`private java.util.List<String> errors;`（errors 为兼容保留一个版本，Javadoc 标注 deprecated-for-removal）。**不要**在类上加 `@JsonInclude`，否则 `data: null` 会从既有成功响应中消失。
       - 移除 `@AllArgsConstructor`（新字段会让它变成 6 参构造，破坏现有 `new Result<>(200, "success", null)` 调用），改为显式两个构造：3 参 `(int code, String message, T data)` 与 6 参 `(int code, String message, T data, String errorCode, List<FieldErrorVO> fieldErrors, List<String> errors)`。保留 `@Data` 与 `@NoArgsConstructor`。
       - 既有 5 个工厂方法签名全部保持不变。新增：`public static <T> Result<T> failure(int code, String errorCode, String message)`（code 与 errorCode 分离）；`public static <T> Result<T> invalidInput(String message, List<FieldErrorVO> fieldErrors)`，返回 code=400、errorCode=`ErrorCode.VALIDATION_INVALID_PARAMETER.getCode()`。
       - 新增链式方法 `public Result<T> withErrorCode(String errorCode)`、`public Result<T> withFieldErrors(List<FieldErrorVO> fieldErrors)`、`public Result<T> withErrors(List<String> errors)`，各自 set 后 `return this`。
       - 保持 4 空格缩进、单行不超过 100 字符（google_checks）。

    3) 改造 `GlobalExceptionHandler` 的三条校验分支，返回类型由 `ResponseEntity<Map<String,Object>>` 改为 `ResponseEntity<Result<Void>>`，HTTP 状态保持 `ResponseEntity.badRequest()`：
       - `handleMethodArgumentNotValid`：遍历 `ex.getBindingResult().getFieldErrors()` 生成 `new FieldErrorVO(fe.getField(), fe.getDefaultMessage(), null)`；再遍历 `ex.getBindingResult().getGlobalErrors()`，字段名取 `ge instanceof FieldError f ? f.getField() : extractField(ge)`。**两条循环都必须存在** —— `MetricRecordValidator` 是类级约束，其 `.addPropertyNode("value")` 只体现在 GlobalError 上，只读 getFieldErrors 会静默丢弃物理极限拦截。合并后 `.limit(20)`。
       - 新增私有方法 `private String extractField(ObjectError ge)`：先尝试 `ge.unwrap(jakarta.validation.ConstraintViolation.class)`，成功则取 `getPropertyPath()` 首个节点名；否则返回字面量 `"_global"`。
       - 同时用 `withErrors(...)` 回填旧的 `field + ": " + message` 字符串列表（保留一个版本），message 取 `getLocalizedMessage(ErrorCode.VALIDATION_INVALID_PARAMETER, request)`。
       - `handleConstraintViolation` 与 `handleValidationException` 同样改用 `Result.invalidInput(...)`；前者把每个 violation 的 `getPropertyPath().toString()` 作为 field，后者无法确定字段时用 `"_global"`，并各自 `.withErrors(...)`。
       - 日志保持 `log.warn`，不打印完整堆栈。

    4) 新建 `hhs-backend/src/test/java/com/hhs/exception/GlobalExceptionHandlerTest.java`（JUnit 5 + AssertJ，直接 new handler 调用，不启动 Spring）：
       - 用 `BeanPropertyBindingResult` 构造：一条 `new FieldError("userThresholdRequest", "metricKey", "指标类型不能为空")` + 一条 `new ObjectError("userThresholdRequest", "健康指标数据校验未通过")`；用 `MethodParameter` 指向本测试类内一个私有空方法的第 0 个参数，构造 `MethodArgumentNotValidException`；请求用 `MockHttpServletRequest`。
       - 断言 HTTP 状态 400；`body.getCode() == 400`；`body.getErrorCode()` 等于 `ErrorCode.VALIDATION_INVALID_PARAMETER.getCode()`；`body.getFieldErrors()` 含 metricKey 项且全局项字段为 `"_global"`；`body.getErrors()` 非空。
       - 断言 21 条违规时 `getFieldErrors().size() == 20`。
    5) 更新 `RealtimeIntegrationTest`：把 `.andExpect(jsonPath("$.code").value(ErrorCode.VALIDATION_INVALID_PARAMETER.getCode()))` 改为 `.value(400)`，保留 `.andExpect(jsonPath("$.errors").exists())`，追加 `.andExpect(jsonPath("$.fieldErrors").isArray())`。该校验分支由字符串 code 收敛为 int 400 是本计划唯一的有意契约变更，只此一处。

    禁止：修改 `parseCodeToInt`；修改 `MetricRecordValidator`；在 Result 上加类级 `@JsonInclude`；改动任何 DTO 注解消息（属 11-02）。
