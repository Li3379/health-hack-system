    **el-button stub 的正确写法（决定下面的 aria-label 断言能否通过，别做错）**：模板里出现的 `aria-label` 属性会被 Vue 归一化为 `ariaLabel` prop。若 stub 声明了 `props: [..., 'ariaLabel']` 却不在模板里渲染它，该值会被当作 prop 吞掉、不会落到 DOM 的 `aria-label` 属性上，断言必然失败。两种可用写法，任选其一并保持一致：
    - 写法 A（推荐）：`props: ['type','size','loading','ariaLabel']`，模板 `'<button class="el-button" :disabled="loading" :aria-label="ariaLabel"><slot /></button>'` —— 显式把 prop 绑回属性。
    - 写法 B：**不**声明 `ariaLabel` 为 prop（`props: ['type','size','loading']`），让 `aria-label` 作为透传 attr 自动落到根 `<button>` 上；此时模板里的 `:disabled="loading"` 仍需要 `loading` 为 prop。
    无论哪种，最后都要断言 `wrapper.find('.el-button').attributes('aria-label')`；若拿到 `undefined`，几乎一定是把 `ariaLabel` 声明成了 prop 却没往模板里绑。

    覆盖：
    - 默认 variant 渲染 `.error-state`，`role === 'status'`，`aria-live === 'polite'`
    - **不**出现 `role="alert"`：`wrapper.attributes('role') !== 'alert'`
    - 无 `retry` → `.error-state__actions` 不存在（`find('.el-button').exists() === false`）
    - 有 `retry` → 按钮存在，可见文本为 `重试`
    - `retryLabel="重新加载阈值列表"` → 按钮 `aria-label` 为该值；不传时 `aria-label === '重试：无法加载阈值列表'`（用 title 值）
    - 点击按钮 → `retry` spy 被调用 1 次
    - `retrying: true` → 根 `aria-busy === 'true'`，按钮 `disabled` 属性存在
    - `variant='forbidden'` → `.error-state__icon-circle` 元素的 class 含 `error-state__icon-circle--muted`
    - `variant='load'` → 同一元素 class 不含 `--muted` 修饰类
    - 空 `description` → `.error-state__desc` 不存在
    - 挂载后 `document.activeElement` 不是该组件内任何元素（不抢焦点）

    aria-label 断言必须作用在 **DOM 属性**上（`attributes('aria-label')`），不是 stub 的 `props('ariaLabel')` —— 后者会让"属性丢失"这个真实缺陷在测试里隐形。
