<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage dismissal → banner visibility | User-writable preference that governs whether a prompt appears |
| store payload → banner copy | The banner enumerates the caller's own missing field labels |
| dashboard mount → completeness endpoint | Every dashboard visit triggers one fetch |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-29 | Repudiation | Dismissal persistence | low | mitigate | A single writer (`store.dismiss()`) sets the ISO timestamp; a test asserts the value is parseable and that the banner disappears, so the 7-day promise is verifiable rather than assumed |
| T-13-30 | Denial of Service | Repeat fetch on dismiss | low | mitigate | Dismissal is pure local state; a test asserts no second `getCompleteness` call, so a user dismissing repeatedly cannot amplify requests |
| T-13-31 | Spoofing | Failure rendered as 0% | high | mitigate | On fetch failure both surfaces are withheld and a test asserts it; a fabricated 0% would tell a complete-profile user they have nothing filled in |
| T-13-32 | Information Disclosure | Banner body | low | mitigate | Only field labels from the payload are rendered as text; no ids, keys or exception text reach the DOM |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs; icons and components are already present |
</threat_model>
