<objective>
Make the health-score response disclose the substitutions it actually performs, by threading an explicit collector through the scorer chain and adding two fields to `HealthScoreVO`.

Purpose: PRF-05 requires disclosure at the real substitution sites, not reconstruction afterwards (D-03). `service/domain/` is pure logic with 19 Spring-free Mockito tests, and `HealthReportServiceImpl` calls `calculateScore` outside any request, so a request-scoped or ThreadLocal collector would throw there. The overload pattern keeps every existing signature working while letting the score path emit `assumptions[]`. `profileCompleteness` rides along so the score page badge can decide whether to render, but the dashboard banner and the profile header read the dedicated endpoint from 13-02 — `HealthScoreServiceImpl` short-circuits to `createDefaultScore()` for users with no metrics, so this VO can never be the primary completeness source.

Output: `AssumptionCollector`, collector-aware overloads on `ProfileScorer` / `MetricsScorer` / `DimensionScoreCalculator`, the aggregating `ScoreCalculator` overload, the two new `HealthScoreVO` fields, the `health:score:v2:` prefix bump, and `ScoreCalculatorAssumptionsTest`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scorer chain → HealthScoreVO | Internal, but the emitted strings are rendered verbatim in the browser and are the only explanation users get |
| Redis → HealthScoreServiceImpl | Cached VOs may predate the current class shape; deserialization uses `activateDefaultTyping` |
| HealthReportServiceImpl (non-request thread) → ScoreCalculator | No SecurityContext and no request scope available |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-09 | Information Disclosure | AssumptionCollector contents | medium | mitigate | Sentences are backend constants with no field names, class names, SQL or exception text; a test rejects any sentence mentioning 血糖/血压 so no false claim about data usage can ship |
| T-13-10 | Tampering | Redis cached HealthScoreVO | medium | mitigate | `CACHE_KEY_PREFIX` bumped to `health:score:v2:` so a pre-Phase-13 serialized VO can never be read into the new class; the reader does not rely on per-field null checks for correctness |
