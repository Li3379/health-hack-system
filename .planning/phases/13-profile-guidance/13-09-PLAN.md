<objective>
Turn the risk page into the place where an incomplete profile is disclosed, explained and optionally repaired in place — without ever blocking assessment creation.

Purpose: PRF-08 requires the page to show what will be estimated and let the user backfill the minimum required fields on the spot, while D-06 forbids a hard block. PRF-06 requires the 基于不完整档案估算 · 完善档案 badge on both result pages. The trigger order is not cosmetic: UI-SPEC Contract 5 and Contract 8 both say assumptions are evaluated before the score, because a panel with an empty list gives the user no reason to backfill. Because the backend now recomputes assumptions on read, the badge and the panel describe the current profile rather than a frozen historical claim.

Output: `prevention/Risk.vue` with the badge, the panel, the three actions and the detail-dialog assumption list, plus `RiskBackfill.spec.ts`.
</objective>

## Trust Boundaries

| risk page form → PUT/POST health-profile | The backfill writes user data through an existing authorized endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-33 | Tampering | Backfill write target | high | mitigate | The panel reuses `createProfile`/`updateProfile`; the backend update path already verifies `existing.getId().equals(id)` and queries by the JWT userId, so a forged profile id cannot write another user's row (13-02 keeps that path unchanged) |

| T-13-35 | Denial of Service | Abandon path | low | mitigate | `cancel()` performs no API call and a test asserts it, so an abandoned attempt cannot trigger a write or a refetch |

| T-13-37 | Spoofing | Badge on a null payload | high | mitigate | The badge component renders only for a non-null number below 100; the page passes `completeness?.score ?? null` and a test asserts no badge on a failed load |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs; all components and icons are already present |
</threat_model>
