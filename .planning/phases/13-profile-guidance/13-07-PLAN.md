## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query → component behaviour | `?focus=` is user-controlled and must not be able to force a focus into an arbitrary element |
| backend fields[] → rendered copy | Reasons are rendered as text and must never be interpreted as markup |
| localStorage dismissal → banner | Handled in 13-08 through the store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-25 | Tampering | ?focus= query | medium | mitigate | The key is matched against `fields[]` membership and `filled === false` before use, and the selector goes through `useFormServerErrors.focusField`, which applies `CSS.escape` and swallows invalid selectors — an attacker-supplied key can only be a no-op |
| T-13-26 | Information Disclosure | Hint copy rendering | low | mitigate | Reasons are rendered via mustache interpolation (text, never `v-html`), so backend copy cannot become executable markup |
| T-13-27 | Repudiation | Promise sentence placement | low | mitigate | A test asserts the sentence appears exactly once, so a future edit cannot multiply it into nine conflicting promises |
| T-13-28 | Denial of Service | Repeated store fetches | low | accept | The store's loading guard (asserted in 13-05) collapses concurrent mounts to one request |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs; the matchMedia block uses the platform API, not a new dependency |
</threat_model>
