<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store payload → component props | A null or partially populated payload must not become a fabricated visual claim |
| component → assistive technology | Symbols (✓/○/×) carry no semantics on their own and need text alternatives |
| page scope → global CSS | The four badge families are shared across four scoped scopes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-21 | Spoofing | EstimateBadge null handling | high | mitigate | `completeness != null && < 100` is asserted for null, undefined and 100, so an old backend or a cached VO cannot produce a false 「完整度 0%」 claim (UI-SPEC 条件收紧) |
| T-13-22 | Tampering | Shared badge CSS | medium | mitigate | All four families live once in `theme.css` and use only existing tokens; a page-level copy would drift and silently break the AA contrast choices |
| T-13-23 | Information Disclosure | Banner body copy | low | mitigate | The body enumerates the caller's own field labels from the payload; no internal key, id or exception text is rendered |
| T-13-24 | Repudiation | Close control semantics | low | mitigate | The × has an explicit verb+object accessible name and emits the same event as 稍后提醒, so a dismissal is always attributable to a named action |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs; all icons come from the already-installed `@element-plus/icons-vue` |
</threat_model>
