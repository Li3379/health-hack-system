<objective>
Expose the authoritative completeness object over HTTP so every guidance surface has one data source, including for users with no profile and no metrics.

Purpose: RESEARCH Summary (一) is the hard constraint — `HealthScoreServiceImpl.calculateScore` short-circuits to `createDefaultScore()` when `!metricValidator.hasAnyData(userId)`, so a `profileCompleteness` field hung only on `HealthScoreVO` would be null for exactly the new users who need guidance. The dashboard banner (score < 60), the profile page header and the risk badge all need `fields[]` (counts, labels, per-field reasons, per-field assumptions), which `HealthScoreVO` cannot carry anyway. A dedicated endpoint is the only shape that serves all four surfaces.

Output: `HealthProfileService.getCompleteness`, its implementation, `GET /api/prevention/profile/completeness`, and the Wave-0 MVC slice test that pins the wire shape.
</objective>
