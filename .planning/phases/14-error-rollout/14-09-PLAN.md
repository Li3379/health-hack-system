<objective>
Convert the health module's twelve call sites and, in the same pass, retire four of the phase's nine hand-written cancel judgements — because they live in these same handlers. This is ERR-08's core deliverable under D-04: a cancel produces zero prompts, and only the shared recognition decides.

The two concerns cannot be separated here. `Alerts.vue:224` and `:239` and `Metrics.vue:200` each wrap their toast in `if (error !== 'cancel')`, so converting the toast without restructuring the handler would either leave the guard in place (failing the ERR-08 check) or leave a `catch` with no presentation for real failures (a worse bug). The split confirm-then-api shape resolves both: the confirm's own catch returns silently and is the *only* silence, and the api's catch goes straight to `showError`, which already recognises all five cancel forms.

`Score.vue` is the phase's subtlest ERR-08 site. Its guard compares `error.name` against two cancelled-request names. After Phase 11 every failure reaching that catch is an `ApiError`, whose `name` is `ApiError`, so **both comparisons always fail and the toast always shows** — including for a genuine cancel. Worse, the guard is defensive code for an abort that never happens: the handler creates an `AbortController` and calls `.abort()` on it, but never passes its `signal` to the request, so the abort is a no-op. The correct change is to stop hand-checking names and let the shared recognition decide; the controller's deadness is documented in the ledger rather than "fixed", because wiring a signal is a behaviour change outside this phase.

The module also carries the phase's last two `error.response?.data?.message` peeks. On an `ApiError` there is no `response` property, so those expressions have always fallen through to their fallback string. Converting them to `showError` actually improves the copy, because the backend's message now wins. Preserving the peek "for safety" would be preserving dead code.

Purpose: bring the module with the highest concentration of cancel guards and dead error peeks into conformance in one coherent pass.

Output: twelve converted sites, four cancel judgements replaced by one shared rule, both dead peeks removed, the three banned 操作失败 copies eliminated, and two specs that prove silence on cancel and exactly-one-toast on failure.

<note>
The ledger's `kind 覆盖` column for each of these rows should list `cancel` alongside the failure kinds, because every one of these handlers can now receive a cancel through the api path — that is precisely what the old guards were trying to intercept, and it is what the `showError` short-circuit handles.
</note>
</objective>
