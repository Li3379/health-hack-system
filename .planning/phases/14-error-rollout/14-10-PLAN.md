<objective>
Convert the largest module (36 call sites across six files) in two tasks, ordered so the deletions come first and the conversions second. This plan implements D-01's user-visible-path rule and D-04's split-confirm shape for the disconnect handler.

The deletions are the phase's most misunderstood change and need to be stated plainly: twelve of the 87 bare calls sit in an `else` after `if (res.code === 200)`. The response interceptor rejects the promise whenever the envelope's code is not 200, so control never reaches that `else` — the code is unreachable. Deleting it is behaviour-preserving, not a feature removal. It is also mandatory rather than optional: a `catch`-only migration would leave a second, permanently-dead presentation path that a future reader would reasonably "fix" by reinstating the toast, and the residue grep could never reach zero while the literal remained.

This plan handles seven of the twelve deletions (four in DeviceSync, two in AIInput, two in AiHistory; OcrInput's one and OcrHistory's two follow in plan 14-11). Doing them inside the same file edits as the real migrations is the only way to keep each file's diff reviewable.

`AIInput.vue` is the module's interesting conversion. It has a private `handleApiError` helper that peeks at `error.response.data.message`, special-cases status 429, and falls back to a default string. Every one of those three behaviours is either dead (the peek, since an `ApiError` has no `response`) or redundant (the 429 copy, since the backend already sends Chinese). Replacing the helper with two `showError` calls removes the helper, its four call sites and its special case at once — but it must be done carefully, because the helper is called from two different contexts with different default messages.

Purpose: the biggest single reduction in bare error calls, with the deletions explicitly accounted for rather than quietly dropped.

Output: three files fully converted, seven deletions documented as behaviour-preserving, two specs proving both the preservation claim and the helper replacement.
</objective>
