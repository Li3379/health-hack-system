<objective>
Lock the phase's result with a gate that cannot silently pass, and hand the browser-only states to a written script with explicit sampling rules. This plan enforces D-05's measured baselines (not the roadmap's stale 90) and produces the D-06 browser-run script.

Two design choices distinguish this plan. First, the four structural checks become a **spec file**, not a list of shell commands in a summary. The research is explicit that a human-run grep is the only thing standing between this phase and a re-introduced bare toast, and a human-run grep is exactly what stops happening after the milestone closes. The precedent already exists in the repo — one spec reads a store file and asserts a string is absent — so the mechanism is proven. Doing all four this way means `test:run` enforces them.

Second, the gate's failure conditions are written down. Each check states what a wrong answer looks like, because the research found three of the four original checks were red for legitimate reasons: a strict no-message-in-stores rule would forbid three success toasts the contract permits, an unexcluded cancel pattern would match the two utility modules that must keep their comparisons, and an over-broad style pattern would match a danger-zone dialogue that legitimately uses the danger token for a non-form surface. Shipping those three unchanged would train the team to ignore the gate.

The gate deliberately omits formatting. That check currently fails on 98 files; including it would make the phase's "all green" claim false for a pre-existing reason, and the correct response is either a separate scoped commit or an explicit waiver — neither of which belongs inside a rollout phase.

Purpose: prove no regression and prove no residue, with both claims machine-enforced.

Output: a residue spec, a completed ledger reconciled to 87, and a UAT script whose every sample states its wait time and its expected reading.

<baseline_note>
The locked baselines are the measured values, not the roadmap's stale 90: backend at least 845, frontend at least 445 across at least 37 files. New tests may only add. The gate asserts "at least", never equality, because this phase adds tests and a future phase may add more.
</baseline_note>
</objective>
