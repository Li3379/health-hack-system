## 对账说明

- **形态分布（5 行）**：4 行 `presentStates-toast`（共享弹窗的提交 catch、save catch 行、test catch 行、delete/init 两个拆分后的 API catch 行）+ 1 行 `状态块`（load 路径）。文件侧的 `grep -c 'presentStates: true'` = **4**，与四个动作型 catch 一一对应：`handleSaveConfig`、`handleTestConfig`、`handleDeleteConfig`、`handleInitDefaults`。
- **`presentStates` 的 floor 是 4，不是 3**：上述四处各自独立携带选项，任何一处缺失都会让对应的 403 静默。`grep -c 'presentStates: true'` = 4 且 `grep -c 'showError('` = 5，差值 1 就是 `loadConfigs`。
- **1 个不可达 `else` 删除**（本 plan 负责 12 个中的 1 个）：见上方「删除记录」，与 save catch 同处第 2 行，证据是拦截器拒绝语义。
- **1 处静默 `catch`**（`DevicePlatformConfig.vue:372`，以及同形的 `:390`）：已拆成「确认 try / 裸 return」+「请求 try / `showError`」，因此真正的失败会呈现、只有取消保持静默（ERR-08）。`grep -n 'User cancelled'` → 0，两处裸 catch 的注释一并消失。
- **共享弹窗为什么也算 `presentStates-toast`**：它不渲染任何 `ErrorState`（模态没有块），与 load 路径恰好相反 —— 这是 14-05 建立的「按文件定规则」的直接应用，不是逐调用点的判断。
