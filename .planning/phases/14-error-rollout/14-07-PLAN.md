<objective>
Wire the phase's highest-risk file and finish the page that hosts the permission block. This plan implements D-02's "a store is not a UI layer" boundary at the page level and D-03's separation between a state block and an action toast.

`UniversalMetricDialog.vue` is mounted by five spec files covering roughly fifty cases, and its stubs are minimal: `el-form-item` is declared with `label` and `prop` only, so `:error` would be dropped on the floor and any inline assertion would pass without testing anything. That is RESEARCH Pitfall 1, and it is the reason this file gets its own plan rather than riding along with a module batch — the stub repair touches four specs that this plan does not otherwise modify, and the repair must be verified file by file.

It also has three submission modes behind one form: blood pressure posts two metrics in parallel, wellness posts one with notes, and the standard path posts one with a trend. A single `useFormServerErrors` instance is correct here because only one mode is active per dialog opening and the field names overlap (`value`, `diastolicValue`, `recordDate`), so three instances would leave stale errors in the inactive modes.

`DevicePlatformConfig.vue` finishes with its three remaining call sites. Two of them need `presentStates: true` and the reason is structural, not stylistic: plan 14-01 gave this page a page-scope block that owns the load path, so a 403 arriving during a *save* must produce a toast — blanking the whole page because one config save was denied would destroy the user's work. That is exactly the "action-type call site with no state block of its own" case `presentStates` exists for, and the ledger must record the reason per Contract 6.1.

Purpose: no shared component is left half-migrated, and no page mixes the state channel with the action channel incoherently.

Output: the shared dialog and the settings page fully wired, five specs repaired for the `:error` prop rather than weakened, one new spec pinning `presentStates`, and the unreachable else branch deleted with the grep evidence that it was unreachable.
</objective>
