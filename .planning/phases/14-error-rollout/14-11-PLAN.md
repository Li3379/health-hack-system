<objective>
Finish the data-input module and convert the prevention module, closing both the phase's deletion count and its remaining module. This plan implements D-01's ledgered-`保持` exemption for client-side pre-checks and D-04's cancel rule.

The OCR component is where D-01's "user-visible path" test gets its edge case. Two of its five call sites run inside a file picker's change handler, before any request is made: they check size and type. They are real, useful, user-facing messages, but they are not API failures, and converting them would require fabricating an `ApiError` to satisfy a signature whose whole purpose is classifying server responses. Contract 6.2 provides for exactly this: mark them `保持` with a reason. The ledger entry is the deliverable, not the conversion. Because there is no `el-form-item` in this component, an inline field-error surface would require restructuring the upload control — so retention is the correct call and the residue is deliberate, documented, and counted.

The same file's recognise handler sets `recognizeResult.status = 'failed'` and then toasts. That assignment is the content-area failed state — a distinct mechanism from the toast, giving the panel a persistent failed result with the error text inside it. The migration must keep the assignment and change only the message path, because dropping it would turn an inline result panel into a bare toast and lose the panel's structure.

`prevention/Metrics.vue` completes the phase's hand-written cancel cleanup: its guard checks two sentinels, the second of which (`'close'`) is never produced by a confirmation dialog. With this plan's change, all nine cancel judgements from the research inventory are gone, and the phase's structural check ③ can pass.

Purpose: close the module count and the cancel count in one plan, since they overlap in exactly these files.

Output: three data-input files and two prevention files converted, the phase's twelve deletions completed, the two 保持 decisions documented with reasons, and two specs pinning both the retention and the silence.
</objective>
