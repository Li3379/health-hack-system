<objective>
Deliver S2 across all three of its real surfaces, and close the last blank screen in the app. This plan implements D-03's content-area-404 rule with zero toast, and its route-level variant.

Two distinct facts shape this plan. First, a 404 arrives in two envelope shapes — a numeric `code: 404` from the static-resource handler and a string `errorCode` with numeric code 500 from any `BusinessException` — and plan 14-01 normalises both to `kind: 'notFound'`. What remains is the rendering split: the screening detail page has a route param, so the page shell is still meaningful and only the report area should be replaced; the comparison page's "参数错误" is a routing state reached before any request, and it currently shows a toast, which is the wrong channel for a URL the user typed or bookmarked. And the router has no catch-all at all, so an unknown URL renders an empty main-content area with no explanation — the single most naked failure surface in the application.

Second, the non-regression constraint. `prevention/Profile.vue` and `stores/profileCompleteness.ts` already treat a not-found as a normal state (create mode / empty completeness). They read `err.status` and `err.code`, which plan 14-01's branch preserves. This plan must not touch either file, and the fact that it does not is itself the evidence that the shared classification change is safe.

Purpose: ERR-07's third leg. Validation goes inline, network gets a retryable toast, and permissions/resources get state blocks — with no channel overlap.

Output: the S2 block on the screening detail page, the routing-state block on the comparison page, a single page-scope NotFound view wired through one catch-all route, and the tests that pin the block's presence, its two actions, and its zero-toast property.

<note>
Read the "Consistency with the trap" note in this plan's task 1 before editing `Compare.vue`: the invalid-param branch must not issue a request first and then classify — the state is knowable before the call.
</note>
</objective>
