# Phase 15 — 风险历史按批次折叠与趋势

**Milestone:** v1.4 风险评估可信化与引擎收敛
**Created:** 2026-11-17
**Depends on:** v1.3 Phase 14（风险评估页现状）

---

## 为什么做这个阶段

上一轮改动（commit `880f108`）已经完成了三件事：

1. `createAssessment` 不再删除历史，改为追加（旧实现每次删光重写）
2. 每条记录带 `batchId`，同一次评估的三条疾病共享一个批次号
3. 归因冻结为 `contributors` JSON 快照，读取原样返回

**但前端完全没用上 `batchId`。** 现在页面上是 9 行平铺的混排记录：

```
糖尿病      中风险  50   ...
高血压      中风险  40   ...
心血管疾病  中风险  44   ...
糖尿病      中风险  50   ...   ← 上一次评估
高血压      中风险  40   ...
心血管疾病  中风险  44   ...
糖尿病      中风险  50   ...   ← 再上一次
...
```

用户看到的是「三行糖尿病、三行高血压」交错，**分不清哪三条属于同一次评估**，也看不出风险在变好还是变差。

数据留了，但用户读不出来。这个阶段就是把已经存下来的东西真正呈现出来。

---

## 范围

### 做

1. **按批次折叠**：表格改为批次卡片，每张卡片 = 一次评估，内含该批次的三条疾病
2. **相对上次的变化**：每项疾病显示与上一批次的分数差（↑ / ↓ / 持平），以及变化幅度
3. **批次时间与摘要**：卡片头部显示评估时间、本次最高风险等级
4. **旧数据兼容**：`legacy-*` 批次（v1.3 之前创建、无归因快照）正常显示，只是不显示明细

### 不做

- 不新增疾病（Phase 16 的事）
- 不改评估引擎的输入（Phase 16）
- 不做图表趋势线（本轮只做文字箭头，图表留待后续）
- 不改表结构（`batchId` 已存在）

---

## 关键决策

<decisions>

- **D-01:** 折叠形态用可折叠卡片，不用表格分组。`el-table` 的分组行（`span-method`）能让同一批次的行合并，但视觉上仍然是一张平铺的表，且「相对上次的变化」无处安放。改用 `<el-collapse>`：每个批次一个面板，标题行显示「2026-11-17 10:53 · 最高风险：中风险」，展开后是该批次的三条疾病；默认展开最近一个批次，其余折叠。**理由**：趋势是跨批次的比较，把每个批次做成独立单元才看得清。

- **D-02:** 变化只与「紧邻的上一个批次」比，不做任意两个批次比。用户关心的是「这次比上次怎么样」，不是「这次比三个月前怎么样」。实现上：批次按时间倒序排列，第 N 个批次的对照组是第 N+1 个；最早的一批没有对照组，显示「首次评估」。

- **D-03:** 变化用绝对分差 + 方向，不用百分比。分数是 0-100 的整数，百分比在小基数上会失真（40 → 44 是 +10%，看起来像大变化，实际只是 4 分）。显示为「44（↑4）」而不是「+10%」。**理由**：风险分数不是比率，用户也不该按比率理解它。

- **D-04:** 等级变化单独标注。分数变化和等级变化是两件事。44 → 46 只涨 2 分，但如果跨过 35 的阈值就是 LOW → MEDIUM，这是用户真正需要知道的。卡片上同时显示分数箭头与等级变化徽标（如「中风险 → 高风险」），两者是并列元素，不得拼进同一段文本。

</decisions>

## 数据契约

前端已有 `RiskAssessmentVO`，`880f108` 已加 `batchId`。本阶段**不需要后端改动**，纯前端分组。

分组逻辑：

```ts
// assessments 按 createTime DESC 返回
const batches = computed(() => {
  const map = new Map<string, RiskAssessmentVO[]>()
  for (const a of assessments.value) {
    const key = a.batchId ?? `legacy-${a.createTime}`
    if (!map.has(key)) map.set(key, [])
    map.get(key)!.push(a)
  }
  return [...map.entries()].map(([batchId, rows]) => ({ batchId, rows, ... }))
})
```

## 验收标准

1. 风险页历史区域按批次折叠，每个批次一个可展开面板
2. 最近批次默认展开，其余默认折叠
3. 每个批次的每项疾病显示与上一批次同疾病的分数差（↑ / ↓ / 持平 / 首次）
4. 跨等级阈值时额外显示等级变化（如「低风险 → 中风险」）
5. `legacy-*` 批次正常渲染，不报错，明细缺失时说明「该记录创建时未保存评分明细」
6. 只有 1 个批次时，所有项显示「首次评估」，不出现「↑0」这类噪音
7. 前端门禁全绿（`test:run` + `build`），后端无改动

## 已知约束

- `legacy-*` 批次的 `contributors` 为 `null`（v1.3 之前没存快照），详情弹窗已有「不渲染明细」的保护，本阶段沿用
- **`RiskBackfill.spec.ts` 没有「表格渲染 3 行」的断言**（初稿此处判断有误，已由 pattern-mapper 核实）。该 spec 的 `el-table-column` stub 是自闭合的，单元格内容根本不可观测；`:287` 与 `:377` 的 `toHaveLength` 断言针对的是数据来源面板与弹窗明细。**因此本阶段对测试只做增补，不删改既有断言。**
- **两个 spec 都缺 `el-collapse` / `el-collapse-item` stub。** 未 stub 的 `<el-collapse>` 会渲染成未知元素并丢弃默认插槽 —— 批次内容静默消失，而所有既有断言照旧通过。这是本阶段最危险的失败模式：测试全绿但功能不存在。两个 spec 都必须补 stub（可复制 `DeviceSyncMigration.spec.ts:171-172` 的写法），并加 `el-empty` stub。
- **`--border-1` 在全站未定义**（`Risk.vue` 独有 8 处误用：705/706/767/802/851/863/980/992），那些 `border` 实际不渲染。新增批次样式必须用已定义的 `var(--border)`。修复那 8 处既有误用属于无测试覆盖的视觉变更，**不在本阶段范围**，留作后续独立事项。
