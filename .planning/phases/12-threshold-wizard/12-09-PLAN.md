<objective>
Close the two UAT gaps of Phase 12 (12-UAT.md §Gaps, test 1 major + test 5 minor):

1. **Gap 1 (major, THR-06 trace):** the wizard did not auto-close after a successful save — parent `wizardVisible` and `props.modelValue` both flipped false, but the Element Plus `.el-overlay` stayed `display:block`. Root cause: the one-way visibility prop binding plus an explicit update handler on `el-dialog` desyncs from EP internals under `destroy-on-close`. Fix: adopt the repo-standard `v-model` + writable computed binding that already works in `UniversalMetricDialog.vue` and `CriticalConfirmDialog.vue`.
2. **Gap 2 (minor, FIX-04 trace):** the SQL repair script's BEFORE/AFTER acceptance counters could never reach 0 under `utf8mb4_*_ci` collation because the counting IN lists contain lowercase concatenation variants (`bloodglucose`, `bodytemperature`, `bloodoxygen`) that are case-insensitively equal to the canonical keys, so canonical rows were miscounted as non-canonical (AFTER stuck at 3/2/7). Fix: make the eight counting predicates case-exact; leave every data-manipulation statement untouched.

Purpose: restore the wizard's save→close contract the user actually walks through, and make the script's operator acceptance criterion (header comment: 执行成功后这些计数必须全部为 0) truthful.
Output: patched `ThresholdWizard.vue` (13-case spec + full frontend suite + build green) and patched `fix-threshold-metric-key.sql` (AFTER counters verified 0 against the running dev MySQL).
</objective>
