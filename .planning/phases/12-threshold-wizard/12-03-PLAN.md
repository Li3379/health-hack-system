  <action>
    Create `hhs-backend/src/main/resources/sql/fix-threshold-metric-key.sql` following the shape verified in RESEARCH §Code Examples, with these mandatory properties. (1) A BEFORE block of SELECT COUNT queries: total `user_threshold` rows, non-canonical `user_threshold` rows, and non-canonical `alert_rule` rows. (2) `START TRANSACTION` immediately after. (3) `user_threshold` family dedupe FIRST (D-14 keep-latest semantics): a derived-table form `DELETE ut FROM user_threshold ut JOIN (SELECT ut2.id FROM user_threshold ut2 JOIN user_threshold cand ON cand.user_id = ut2.user_id AND <canon>(cand.metric_key) = <canon>(ut2.metric_key) AND (cand.updated_at > ut2.updated_at OR (cand.updated_at = ut2.updated_at AND cand.id > ut2.id))) AS loser ON loser.id = ut.id` — where `<canon>(k)` is the same CASE mapping the rename uses (bloodGlucose / bodyTemperature / bloodOxygen families); because the join matches by canonical FAMILY rather than by literal key, every alias combination collapses to the single latest row per (user_id, family): a newer alias row beats an older canonical row (D-14 "reflect the user's most recent intent"), and two same-family alias rows (e.g. `glucose` + `GLUCOSE`) never both survive into the rename, so `uk_user_metric` can never abort with Duplicate entry. The derived table remains mandatory because MySQL 8 forbids deleting from and selecting from the same table in one subquery. (4) Then the `UPDATE user_threshold SET metric_key = CASE ... END WHERE metric_key IN (<full alias set>)`. (5) The same dedupe-then-rename pair for `alert_rule` covering glucose → bloodGlucose and temperature → bodyTemperature (D-15). (6) Plain UPDATEs for `alert_template` and `health_alert` (no unique index on those keys). (7) `COMMIT`, then an AFTER block of SELECT COUNT queries whose non-canonical counts must be zero. The alias set used in every WHERE and CASE must include all of: glucose, GLUCOSE, glu, GLU, blood_glucose, BLOOD_GLUCOSE, bloodglucose for the bloodGlucose family; temperature, TEMPERATURE, temp, TEMP, body_temperature, BODY_TEMPERATURE, bodytemperature for the bodyTemperature family; spo2, SPO2, blood_oxygen, BLOOD_OXYGEN, bloodoxygen for the bloodOxygen family. Add a header comment block naming: purpose, idempotency guarantee, the mandatory code-before-script execution order, and the rollback boundary (no automatic reverse mapping exists). Do NOT add a Flyway header, do NOT make it run at application startup (D-13 forbids both).
