<objective>
Normalize `metricKey` to its canonical form on both write paths and make every threshold read alias-aware, so a threshold saved as `glucose` and a threshold saved as `bloodGlucose` are the same configuration to the alert engine.

Purpose: FIX-02 and FIX-03 are what turn "I configured it" into "it fires". Without them the unique index rejects the canonical insert (500) or the engine queries an alias the row was never written under (silent miss). This plan also removes the `selectOne` + alias-`IN` landmine before it can explode: `BaseMapper.selectOne(Wrapper)` delegates to `selectOne(wrapper, true)` and throws `TooManyResultsException` when two rows match.
Output: Canonical writes, alias-aware reads across the threshold service and all four alert-side query sites, plus the tests that pin both behaviours.
</objective>
